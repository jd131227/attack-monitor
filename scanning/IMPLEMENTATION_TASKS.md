## 0. 「完全」の定義（このタスクの合格条件）

本タスクは、以下を**すべて**満たしたときにのみ「完了」とする。曖昧な自己判断は禁止。

1. 第 4 章「実装すべき項目」の全項目が実装されている。
2. 第 5 章「テスト」のテストがすべて**実際に実行され、パスする**。
3. コードに残った `TODO` / `FIXME` / 「未実装」コメントが**ゼロ**になっている
   （`grep -rn "TODO\|FIXME\|未実装" .` の結果が空）。
4. `make` が警告なしでビルドでき、`make test`（C）と `pytest`（Python）が緑になる。
5. 第 6 章「完了の証明」に書いた全コマンドを実行し、その出力を
   `VERIFICATION.md` に貼り付けて成果物として残している。

> 上記 5 を満たさない限り「完成しました」と報告しないこと。
> どこかが満たせない場合は、満たせない理由と現状を正直に報告し、勝手に妥協しないこと。

## 1. 前提・進め方

- 作業前に `server-attack-monitor-spec.md`（仕様書）と既存コードを**必ず読む**。
- 既存の設計方針を踏襲する:
  - コア処理は **C**（`monitor_core.c` / `.h`）。集計・IP 検証・許可照合。
  - 駆動は **Python**（`monitor.py`）が `ctypes` で C を呼ぶ。
  - C では**ポインタと再帰を意図的に使い**、各使用箇所に日本語コメントを付ける。
  - バイト/ビット演算に依存せず、構造体・配列・文字列で素直に書く
    （CIDR のビットマスクなどネットワーク計算上必要な箇所は例外として可）。
- **破壊的操作（ファイアウォール変更）を伴うため**、実機の FW を実際に叩く処理は
  必ず「dry-run 既定」「`--yes` で実行」「適用前バックアップ」「ロールバック可能」にする。
- 各機能を実装するたびに**対応するテストを書き、その都度実行**して緑を確認する
  （まとめて最後にテスト、ではなく逐次）。

## 4. 実装すべき項目（すべて必須）

### 4.1 ファイアウォール実適用（apply-firewall）
- バックエンドを自動判別する: `ufw` → `firewalld` → `nft` の順で存在を確認
  （設定 `FW_BACKEND` で明示指定も可）。
- 適用内容: **SSH 対象ポート（既定 22）をデフォルト拒否**にし、
  許可 IP リスト（`ALLOWED_IPS_FILE`）の各エントリからのみ許可。
  `EXPECTED_PORTS` の他ポート（80/443 等）は従来どおり通す。
- バックエンドごとのルール生成は関数で分離（`_apply_ufw` / `_apply_firewalld` / `_apply_nft`）。
- **dry-run（既定）**では生成予定コマンドを表示するだけで一切変更しない。
  `--yes` で実適用。実適用時のみ後述の安全装置を必ず通す。

### 4.2 安全装置（ロックアウト防止・最重要）
実適用の前に、以下を**この順序で**必ず行う:
1. 現在 SSH 接続中の接続元 IP を検出（`ss`/`who` 等）。
2. その IP が許可リストに**無い**場合、「適用するとあなたが切断される可能性」を警告し、
   `--yes` に加えて `--force` が無ければ**中止**する。
3. 適用直前の FW 状態をファイルにバックアップ（`fw_backup_<timestamp>`）。
4. **許可ルールを先に入れてから**デフォルト拒否を適用する（既存セッションを切らない順序）。
5. 失敗時・検証 NG 時に**バックアップからロールバック**できる関数を用意し、例外時に呼ぶ。
6. `rollback` サブコマンドで、直近バックアップへ手動復帰できるようにする。

### 4.3 TTL 自動失効
- 許可エントリの `# expires=<ISO8601>` を解釈する。
- `Monitor.tick()` の各周回で期限切れエントリを検出し、
  リストから削除 → （実適用モードなら）FW から該当許可を撤去 → 監査ログに記録。
- サービス再起動後も期限が維持されるよう、`ALLOWED_IPS_FILE` に永続化されている前提で動かす。

### 4.4 監視項目の拡張（仕様書 3.2〜3.4）
新たな C 関数 + Python 連携、または Python 単体で実装（重い集計は C 推奨）:
- **不審な接続元 IP（3.2）**: `ss -tn state established` を解析し、
  同一 IP の同時接続数が `CONN_THRESHOLD` 超で警告。許可 IP・`WHITELIST_IPS` は除外。
- **ポートの変化（3.3）**: `ss -tlnp` の LISTEN ポートを取得し、
  `EXPECTED_PORTS` に無いポートが開いたら警告。
- **不審プロセス（3.4）**: CPU/メモリ高負荷プロセスを検出。`PROC_WHITELIST` 除外。
- 各検知は独立関数にして、ループから順に呼ぶ。どの攻撃兆候かをコメント明記。

### 4.5 アラート通知フック（仕様書 5.3）
- `notify(event: dict)` を 1 箇所に用意。既定は標準出力 + ログ追記。
- Slack / メール / Webhook を後から差し込めるよう、設定で有効化できる雛形コメントを残す
  （ネットワーク送信の実体は任意。最低限フック関数と呼び出し点を作る）。

### 4.6 ログローテーション（仕様書 5.2）
- `LOG_FILE` が `LOG_MAX_BYTES` を超えたら `.1` へ退避して新規作成（簡易ローテート）。

### 4.7 C のメモリ安全性
- 追加する C 関数も `malloc` の戻り値チェック・`free` 徹底・配列境界に注意。
- 既存テストに加え、可能なら `valgrind` でリーク無しを確認（無い環境ではコードレビューで担保）。

## 5. テスト（必須・実行して緑にする）

### 5.1 C ユニットテスト（`test_core.c` を拡張、`make test`）
- 既存（集計・失効・分類・許可照合）に加え、新 C 関数があればテストを追加。
- 異常系: NULL 入力、空リスト、巨大入力で落ちないこと。

### 5.2 Python テスト（`pytest`、`tests/` 配下）
- **FW コマンドは実行せずモック**する（`subprocess` をモンキーパッチ）。本物の FW は絶対に叩かない。
- 最低限カバーするケース:
  - `allow-ip`/`remove-ip`/`list-ips` の永続化と CIDR・不正 IP 拒否。
  - `apply-firewall` が **dry-run では subprocess を呼ばない**こと。
  - 安全装置: 接続中 IP が未許可なら `--force` 無しで**中止**すること（モックで接続中 IP を注入）。
  - TTL: 期限切れエントリがループで除去され、監査ログに記録されること（時刻をモック）。
  - 差分ログ読み: 追記分だけ取り込み、ローテーション後は先頭から読むこと。
  - 監視拡張: `ss` 出力をモックして接続過多・未知ポートを検知すること。
- `pytest -q` がすべて緑であること。

### 5.3 統合スモークテスト（`tests/smoke.sh`）
- 一時ディレクトリに偽 `auth.log` と設定を作り、`run` を数秒回して
  「総当たり検知 → `Ctrl+C` 相当で安全停止」をログで確認するスクリプト。
