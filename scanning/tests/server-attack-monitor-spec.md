# サーバー攻撃検知 監視スクリプト 仕様書

> このドキュメントは Claude Code への実装指示書です。
> 自分が所有・管理するサーバーの防御（ブルーチーム）を目的としています。
> 他者のシステムへの無許可の調査・攻撃には使用しません。

---

## 0. 運用上の前提（コードを動かす前に）

本ツールは**本番サーバーのファイアウォールを実際に書き換え、SSH を許可 IP に絞り込む**。
設定を誤ると自分やチームがサーバーに入れなくなる（ロックアウト）リスクがあるため、
実装・実行の前提として以下を満たすこと。

- 対象サーバーは**自分が管理権限を持つ／社内で正式に許可された範囲**に限る。
- 本番適用の前に、上長またはセキュリティ担当の**承認**を得る。
- まず**検証環境（または使い捨ての VM / コンテナ）で必ず動作確認**してから本番へ。
- 本番適用時は、SSH 以外の復旧手段（コンソール / KVM / クラウドのシリアルアクセス等）を
  確保しておく。
- アクセス制御の変更は必ず `--dry-run` で確認 → 接続中 IP 警告を確認 → 適用、の順で行う。

---

## 1. 目的

自分で運用している Linux サーバーに対する攻撃の兆候を、常時ループで監視し、
異常を検知したらアラートを出すツールを作成する。あわせて、SSH(22番) を
許可 IP のみに絞るアクセス制御と、作業時に守りを止めず共存させる機能を備える。

本ツールが行う能動的防御は、**許可 IP リストに基づく SSH アクセス制御（4.5）に限定**する。
これは管理者が明示的に設定する静的な制御であり、
「攻撃を検知したら動的に IP を遮断する」種類の自動ブロックは行わない
（その用途が必要なら `fail2ban` 等に委譲する。9 章参照）。

---

## 2. 対象環境

- **OS**: Linux（Ubuntu / Debian 系を第一想定。RHEL 系もできれば考慮）
- **権限**: ログ閲覧のため root もしくは sudo 実行を前提としてよい。
- **常駐方法**: 単発のループ実行に加え、systemd サービスとして常駐できる構成を用意する。

### 2.1 実装言語の方針（重要）

- **コア処理は C 言語で実装する**（メイン）。
  - ログ解析・集計・しきい値判定などの中心ロジックはすべて C 側に置く。
  - Bash は使わない。文字列・数値処理はバイト/ビット演算ではなく、
    C の標準的なデータ構造（構造体・配列・文字列）で素直に書く。
- **Python を「駆動役（ドライバ）」とする。**
  - Python から C を呼び出して動かす。ループ制御・スケジューリング・
    起動/停止・設定読み込み・出力整形は Python 側で担当する。
  - C との連携方法は次のいずれかを採用（実装者が選定し README に明記）:
    1. C を共有ライブラリ（`.so`）にして Python の `ctypes` から呼ぶ（推奨）。
    2. C を実行ファイルにビルドし、Python から `subprocess` で呼ぶ。
  - `ctypes` を使う場合、Python ↔ C の境界は**ポインタ受け渡し**で設計する
    （構造体ポインタや配列ポインタを介して結果を返す）。

### 2.2 C 実装で必須とする技法

以下を**意図的に用いること**。各使用箇所にはコメントで目的を記す。

- **ポインタ**:
  - 関数間のデータ受け渡しは値コピーではなく**ポインタ経由**を基本とする。
  - 集計結果（IP ごとの失敗回数など）は構造体ポインタで返す。
  - 動的確保（`malloc`/`free`）したバッファはポインタで管理し、解放漏れを防ぐ。
- **再帰**:
  - ツリー的・反復的に分解できる処理は**再帰関数**で実装する。
    - 例: ログファイルを行単位で再帰的に走査する読み取り関数。
    - 例: IP 集計を保持する連結リスト/二分木を**再帰的にたどって**集計・表示する。
  - 再帰には必ず明確な基底条件（base case）を置き、深さの暴走を防ぐ。
- メモリ安全性に配慮し、確保したポインタは必ず解放する（リーク禁止）。

## 3. 監視項目（必須）

各項目は「しきい値を超えたら警告」という形で実装する。
しきい値は後述の設定ファイルで変更できること。

### 3.1 SSH ログイン失敗（総当たり攻撃の検知）
- `/var/log/auth.log`（Debian系）または `/var/log/secure`（RHEL系）を解析。
- `Failed password` / `Invalid user` の発生回数を**単位時間あたり**でカウント。
- 同一 IP からの失敗回数を集計し、しきい値超過の IP を警告として列挙する。

### 3.2 不審な接続元 IP
- 現在の確立済み接続（`ss -tn state established` 等）を取得。
- 短時間に多数の接続を張っている IP を検出。
- 既知の許可 IP（ホワイトリスト）は除外できること。

### 3.3 ポートの変化
- 現在 LISTEN しているポート一覧（`ss -tlnp`）を取得。
- 「想定ポート一覧（設定ファイル）」と比較し、**未知のポートが開いた**場合に警告。

### 3.4 不審なプロセス
- CPU / メモリ使用率が異常に高いプロセスを検出。
- 既知の正常プロセス名はホワイトリストで除外可能にする。

---

## 4. 監視項目（任意・あれば尚良し）

- `sudo` の実行履歴の急増検知。
- 新規ユーザー/グループの追加検知（`/etc/passwd` の変更監視）。
- ディスク使用率の急増（ログ汚染・データ流出の兆候として）。
- 外向きの大量通信の検知。

---

## 4.5 SSH アクセス制御 / 許可 IP 管理機能（重要・追加要件）

監視（見張る）だけでなく、**「許可した IP 以外は SSH に入れない」状態を作る**機能を実装する。
目的は「許可した人以外の侵入をなくす」こと。通常の通信（Web の 80/443 など）は妨げない。

### 4.5.1 方針
- ファイアウォール（Debian系=`ufw`、RHEL系=`firewalld`、無ければ `nftables`）を用いる。
- **SSH(22番)はデフォルト拒否**とし、**許可 IP リストに載った IP からのみ許可**する。
- 22番以外の必要ポート（例: 80/443）は従来どおり通す。設定で指定可能にする。
- 監視機能の `WHITELIST_IPS`（アラート除外）とは別概念だが、
  許可 IP は自動的にアラート除外にも反映してよい。

### 4.5.2 IP 追加機能（必須）
- コマンドで**許可 IP を後から追加**できること。例:
  - `monitor.py allow-ip 203.0.113.5`
  - 任意でコメント付与（誰の IP かのメモ）: `monitor.py allow-ip 203.0.113.5 "自宅"`
- 追加した IP は**永続化**する（許可 IP リストファイル、例: `allowed_ips.conf`）。
  再起動・再適用後も維持されること。
- 一覧表示・削除も用意する:
  - `monitor.py list-ips` / `monitor.py remove-ip 203.0.113.5`
- CIDR（例: `203.0.113.0/24`）も受け付けられること。
- 不正な IP 文字列は弾き、エラーメッセージを出す（入力バリデーション）。

### 4.5.3 安全装置（ロックアウト防止・必須）
> 自分で自分を締め出す事故を防ぐため、以下を必ず実装する。

- ルール適用の**前に**、現在接続中の SSH 接続元 IP を検出し、
  許可リストに無ければ「このまま適用すると自分が切断される可能性がある」旨を警告し、
  確認（`--yes` などの明示同意）が無ければ中止する。
- 既存の SSH セッションを切らない適用順序にする
  （拒否ルールより先に許可ルールを入れる）。
- 適用直前のファイアウォール状態をバックアップし、ロールバックできるようにする。
- ドライラン（`--dry-run`）で、実際に変更せず適用予定のルールを表示できること。

### 4.5.4 C / Python の役割分担
- **IP の検証・正規化・CIDR 判定・許可リストの照合**などのロジックは C 側で実装する
  （前述のポインタ／再帰方針に従う。例: 許可リストを連結リストで保持し再帰的に照合）。
- ファイアウォールコマンドの実行・永続化・CLI サブコマンドの受け口は Python ドライバが担当。

## 4.6 作業モード / メンテナンス・テスト共存機能（追加要件）

社内で正式に許可された検査・メンテナンス作業を行う間も、
**監視ループは止めずに動かし続けたまま**、自分の作業だけは妨げられないようにする機能。
「守りながら作業する」ための仕組み。

### 4.6.1 基本方針
- ループと記録は**常に継続する**（守りを完全停止しない）。
- 作業者の端末 IP（および作業内容）を**一時的に例外扱い**にすることで、
  自分の作業はアラートで埋もれず、SSH からも締め出されないようにする。
- 例外は**期限付き**にし、解除し忘れても自動で元の防御状態へ戻る。

### 4.6.2 機能
- 作業モードの開始/終了コマンド:
  - `monitor.py work-mode start --ip <作業端末IP> --duration 2h --reason "社内検査チケット#123"`
  - `monitor.py work-mode stop`
  - `monitor.py work-mode status`
- 作業モード中の挙動:
  - 指定 IP からの SSH を許可リストに**一時追加**（4.5 の許可IP管理を利用、TTL付き）。
  - 指定 IP を**発生源とするアラートは抑制**（記録は残すが警告は出さない／別ラベルにする）。
  - それ以外の IP に対する監視・検知・記録は**通常どおり継続**する。
- 一時例外は `--duration` 経過後に**自動失効**し、防御状態へ復帰する。
- すべての作業モード操作（開始・対象IP・理由・終了）を**監査ログに必ず記録**する。

### 4.6.3 重要な原則
- 作業モードは「全停止」ではない。**自分の作業だけを通し、他は守り続ける**。
- 作業対象は**自分が管理権限を持つ／社内で正式に許可された範囲のみ**を前提とする。
  本機能は他者システムへの無許可アクセスを助けるものではない。

## 5. 動作仕様

### 5.1 ループ動作
- メインループは「収集 → 評価 → 出力 → スリープ」を繰り返す。
- スリープ間隔（デフォルト 10 秒）は設定で変更できること。
- `Ctrl+C`（SIGINT/SIGTERM）で安全に停止し、終了メッセージを出すこと。

### 5.2 出力
- 1 周ごとに、タイムスタンプ付きで現在のステータスを 1〜数行で表示。
- 正常時は簡潔に、異常検知時は目立つ形（`⚠️` や色付き）で警告。
- すべての出力は同時にログファイル（例: `/var/log/attack-monitor.log`）へ追記。
- ログはローテーション可能なサイズで肥大化を防ぐ配慮をする。

### 5.3 アラート（拡張ポイント）
- 警告発生時に外部通知を呼べるよう、**フック関数**を 1 箇所に切り出しておく。
  - 初期実装は標準出力 + ログ追記のみでよい。
  - 後から「Slack / メール / Discord webhook」を差し込めるコメントを残す。

### 5.4 集計・解析の定義（実装者が迷わないための明確化）

- **時間窓**: しきい値判定は「現在時刻から過去 `WINDOW` 秒」を対象に集計する
  （累計ではなくスライディングウィンドウ）。古いイベントは窓から外れたら集計対象から外す。
- **ログ読み取り方式**: ログは毎回先頭から全読みしない。**前回読み取り位置（オフセット）を保持し、
  差分のみ読む**こと。ログローテーションで inode が変わった場合は先頭から読み直す。
- **状態の保持**: IP ごとの失敗回数・接続数などの集計状態は C 側のデータ構造
  （連結リスト/ハッシュ/二分木）で保持し、窓から外れた古いエントリは再帰的に走査して削除する。
- **IPv4 / IPv6**: `ENABLE_IPV6=true` の場合は IPv6 アドレスも検証・集計・制御対象とする。
  IP の検証関数は IPv4 / IPv6 / CIDR を判別できること。
- **時刻の扱い**: ログのタイムスタンプはサーバーのローカル時刻基準で解釈する
  （年をまたぐログ等のエッジケースは「直近 `WINDOW` 秒」で判定する設計上、影響を最小化する）。

### 5.5 一時例外（TTL）の失効管理

- 作業モード等で付与した**一時許可 IP / アラート抑制には有効期限（TTL）**を持たせる。
- 失効の確認は**メインループの各周回の中で行う**（別タイマープロセスは作らない）。
  期限切れのエントリを検出したら、許可ルール・抑制設定を解除し、監査ログに記録する。
- サービス再起動後も TTL が維持されるよう、期限情報は永続化ファイルに保存する。

## 6. 設定ファイル

スクリプト本体と分離した設定ファイル（例: `monitor.conf` もしくはスクリプト冒頭の変数群）に以下を持たせる。

| 設定項目 | 説明 | デフォルト例 |
|---|---|---|
| `INTERVAL` | ループ間隔（秒） | `10` |
| `WINDOW` | しきい値判定の対象とする時間窓（直近何秒を集計するか） | `300` |
| `SSH_FAIL_THRESHOLD` | 時間窓内の SSH 失敗許容数 | `20` |
| `CONN_THRESHOLD` | 同一 IP の同時接続許容数 | `50` |
| `WHITELIST_IPS` | アラート除外する IP（自分の作業端末など） | 空 |
| `EXPECTED_PORTS` | 開いていて当然のポート一覧 | `22 80 443` |
| `ALLOWED_SSH_PORTS` | SSH として制御する対象ポート | `22` |
| `PROC_WHITELIST` | 除外する正常プロセス名 | 空 |
| `LOG_FILE` | 監視出力ログのパス | `/var/log/attack-monitor.log` |
| `AUDIT_LOG_FILE` | 操作・作業モードの監査ログのパス | `/var/log/attack-monitor-audit.log` |
| `ALLOWED_IPS_FILE` | SSH 許可 IP リストの永続化先 | `/etc/attack-monitor/allowed_ips.conf` |
| `FW_BACKEND` | ファイアウォール（`auto`/`ufw`/`firewalld`/`nft`） | `auto` |
| `BRIDGE_MODE` | C との連携方式（`ctypes`/`subprocess`） | `ctypes` |
| `ENABLE_IPV6` | IPv6 アドレスも監視・制御対象にするか | `true` |
| `LOG_MAX_BYTES` | ログローテーションのサイズ上限 | `10485760` |

## 7. 成果物

1. **C ソース**（例: `monitor_core.c` / `monitor_core.h`）— コア監視・集計ロジック
2. **Python ドライバ**（例: `monitor.py`）— C を呼び出してループ駆動する
3. **ビルド手順**（`Makefile` もしくは `build.sh`）— C を `.so` または実行ファイルに
4. **設定ファイル**（`monitor.conf` または Python 側の設定）
5. **許可 IP リストファイル**（例: `allowed_ips.conf`）＋ IP 追加/削除/一覧の CLI
6. **systemd ユニットファイル**（`attack-monitor.service`）— 常駐用（Python ドライバを起動）
7. **README.md** — ビルド/セットアップ手順、実行方法、停止方法、しきい値調整、
   C↔Python 連携方式（ctypes / subprocess）の説明
8. ログサンプル（正常時・異常検知時の出力例）

## 8. コード品質の要件

- **C 側**: コンパイルは警告ありで通す（`-Wall -Wextra` 推奨）。
  `malloc` の戻り値チェック、`free` によるリーク防止、配列境界に注意する。
- **C 側**: ポインタと再帰の使用箇所には、目的を説明する日本語コメントを必ず付ける。
- **Python 側**: 例外で落ちずに警告して継続する。`Ctrl+C` で安全に停止する。
- ログファイルが存在しない/読めない場合も落ちずに警告して継続する。
- Debian 系・RHEL 系でログパスを自動判別する。
- 各監視処理は独立した関数（C 側）/モジュール（Python 側）に分け、追加・削除しやすくする。
- コメントは日本語で、各監視項目が「何の攻撃の兆候か」を明記する。

---

## 9. 明確な非責務（やらないこと）

- 他者・外部システムへのスキャンや攻撃は**一切行わない**。
- SSH 以外のポートに対する自動ブロックは行わない（必要なら `fail2ban` を推奨として README に明記）。
  - ※ SSH(22番) のアクセス制御は「4.5 SSH アクセス制御 / 許可 IP 管理機能」で扱う。
    これは許可リストに基づく**明示的な制御**であり、攻撃検知に応じた動的ブロックとは別物。
- 本格的な侵入検知が必要な場合は `Suricata` / `Snort`、ファイル改ざん検知は `AIDE` を
  併用するよう README に案内を入れる。

## 10. 受け入れ条件（完成の定義）

- [ ] コア処理が C で実装され、Python ドライバから呼び出して動作する。
- [ ] C 側でポインタ（構造体/配列ポインタ・動的確保）と再帰関数が実際に使われている。
- [ ] エラーなくループ実行でき、`Ctrl+C` で安全に停止する。
- [ ] SSH ログイン失敗を集計し、しきい値超過時に IP 付きで警告する。
- [ ] 未知のポートが開いた際に検知・警告する。
- [ ] 設定ファイルでしきい値・ホワイトリストを変更できる。
- [ ] SSH(22番) がデフォルト拒否で、許可 IP リストの IP のみ接続できる。
- [ ] `allow-ip` / `remove-ip` / `list-ips` コマンドで許可 IP を管理でき、永続化される。
- [ ] CIDR と不正入力のバリデーションが機能する。
- [ ] ロックアウト防止（接続中IP警告・ロールバック・`--dry-run`）が動作する。
- [ ] 作業モードで、監視ループを止めずに指定IPのアラート抑制＆一時SSH許可ができる。
- [ ] 作業モードの一時例外が `--duration` 経過後に自動失効し、操作が監査ログに残る。
- [ ] systemd サービスとして常駐起動できる。
- [ ] README に導入・運用・停止手順が記載されている。
